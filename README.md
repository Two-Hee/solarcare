# 솔라케어 (SolarCare) 홈페이지

태양광발전설비 발전저하 원인진단 · O&M 유지보수 사이트.
빌드 도구 없는 정적 사이트로, GitHub Pages 에 그대로 올라갑니다.

- 저장소: `Two-Hee/solarcare`
- 공개 주소: <https://two-hee.github.io/solarcare/>

---

## 1. 배포 방법

1. 이 폴더의 파일 전체를 `Two-Hee/solarcare` 저장소에 올립니다.
2. GitHub 저장소 → **Settings → Pages** 로 이동
3. **Source: Deploy from a branch** / **Branch: `main`** / **Folder: `/ (root)`** 선택 후 Save
4. 1~2분 후 <https://two-hee.github.io/solarcare/> 접속

저장소는 **Public** 으로 두세요. Private 저장소에서 Pages 를 공개하려면 유료 플랜(Pro)이 필요합니다.

> ⚠️ **고객 데이터는 절대 커밋하지 마세요.**
> 발전량 원본 데이터, 고객사명, 발전소 주소, 계약서 등은 한 번 커밋하면 나중에 파일을 지워도
> git 히스토리에 영구히 남습니다. 이 사이트는 그런 데이터를 담지 않는 구조로 만들었습니다.

## 2. 로컬에서 미리보기

HTML 파일을 더블클릭해 열면 `site.json` 을 불러오지 못합니다(브라우저 보안 정책).
화면은 정상 동작하지만 전화번호 등이 기본 placeholder 로 보입니다.
정확히 확인하려면 이 폴더에서 로컬 서버를 띄우세요.

```bash
python -m http.server 8080
```

그 후 브라우저에서 <http://localhost:8080/> 접속.

> `404.html` 만은 로컬에서 스타일이 깨져 보입니다. 이 파일은 GitHub Pages 의 하위 경로
> 구조에 맞춰 절대경로(`/solarcare/...`)를 쓰기 때문입니다. 배포 후에는 정상입니다.

## 3. 가장 먼저 할 일 — `site.json` 채우기

회사 정보는 **`site.json` 한 곳에서만** 관리합니다. 페이지마다 고칠 필요가 없습니다.

| 항목 | 설명 |
|---|---|
| `ceo` | 대표자 실명 |
| `bizNo` | 사업자등록번호 |
| `tel` / `telHref` | 표시용 번호 / 전화 링크용 번호(하이픈 없이) |
| `email` | 문의 회신용 이메일 |
| `address` | 사업장 주소 |
| `kakaoChannel` | 카카오톡 채널 주소. **비워두면 버튼이 자동으로 숨겨집니다.** |
| `formEndpoint` | 문의 폼 전송 주소. 비워두면 메일 프로그램 방식으로 동작합니다. |

### 문의 폼을 실제로 받으려면

GitHub Pages 에는 서버가 없어서 폼을 자체 처리할 수 없습니다. 무료 대행 서비스를 쓰면 됩니다.

1. [Formspree](https://formspree.io) 에 가입하고 폼을 하나 만듭니다.
2. 발급된 주소(`https://formspree.io/f/xxxxxxx`)를 `site.json` 의 `formEndpoint` 에 넣습니다.
3. 끝. 문의가 이메일로 옵니다.

`formEndpoint` 가 비어 있는 동안에도 폼은 동작합니다 — 입력 내용을 정리해 방문자의 메일
프로그램으로 넘겨줍니다.


**Pretendard** (SIL Open Font License 1.1 — 상업적 사용 무료).
현재 jsDelivr CDN 으로 불러옵니다. 외부 의존을 없애고 속도를 더 올리려면:

> 타사 기업 전용서체(통신사·대기업 CI 서체 등)는 대부분 "타 브랜드 아이덴티티 표현 용도
> 사용 금지" 조항이 있습니다. 업종이 겹치지 않아도 라이선스 위반이 될 수 있으므로 쓰지 마세요.

### 보유 자격 표기 ⚠️

`about.html` 에 자격 6종을 넣어두었습니다 —
전기기사 · 전기공사기사 · 소방설비기사(전기) · 신재생에너지발전기사 · 에너지진단사 · 온실가스기사.

**자격 명칭은 자격증에 인쇄된 정식 명칭과 일치시키세요.** 국가기술자격의 정식 명칭이
아래처럼 더 긴 경우가 있습니다. 실제 자격증을 보고 맞는 쪽으로 고쳐주세요.

| 사이트 현재 표기 | 정식 명칭일 가능성 |
|---|---|
| 소방설비기사 (전기) | 소방설비기사(전기분야) |
| 신재생에너지발전기사 | 신재생에너지발전설비기사(태양광) |
| 온실가스기사 | 온실가스관리기사 |

정식 명칭으로 적는 편이 검색 노출에도 유리하고, 자격을 확인하려는 발주자에게 신뢰를 줍니다.
반대로 **보유하지 않은 자격이나 부정확한 명칭은 표시광고법 위반 소지가 있으니** 넣지 마세요.

수정할 위치는 두 곳입니다 — `about.html` 의 `<div class="certs">` 블록(자격 카드),

## 6. 페이지 추가하는 방법

1. 가장 비슷한 기존 페이지를 복사합니다 (`services/index.html` 등).
2. `<html data-root="...">` 값을 폴더 깊이에 맞게 고칩니다.
   - 루트 파일 → `./`
   - 한 단계 하위 폴더 → `../`
3. `<body data-page="...">` 에 고유한 이름을 넣습니다. 헤더 메뉴의 `data-nav` 와 같으면
   해당 메뉴가 자동으로 활성화 표시됩니다.
4. `<title>`, `description`, `canonical`, `og:*` 를 새 페이지 내용으로 바꿉니다.
5. `sitemap.xml` 에 `<url>` 블록을 추가합니다.
6. 헤더 · 푸터 · 모바일바를 **모든 페이지에서 동일하게** 유지합니다.

### 헤더/푸터 중복에 대해

지금은 SEO(특히 네이버 크롤러)를 위해 헤더·푸터를 각 HTML 에 직접 넣어두었습니다.
JavaScript 로 주입하면 크롤러가 메뉴 링크를 놓칠 수 있기 때문입니다.

**대신 메뉴를 하나 추가하면 10개 파일을 모두 고쳐야 합니다.** 현재 페이지 수가
이미 그 한계선(10개)에 도달했으므로, 다음에 페이지를 더 늘릴 때는 Astro 같은
정적 사이트 생성기로 옮기는 것을 권합니다.
그때 `tokens.css` / `components.css` / `site.json` 은 **그대로 재사용**할 수 있게 설계해 두었습니다.

메뉴를 고칠 때 빠뜨리지 않도록, 헤더가 들어 있는 파일 목록입니다 —
`index.html` · `about.html` · `contact.html` · `404.html` ·
`services/index.html` · `cases/index.html` · `cases/sample-shading-loss.html` ·
`tools/index.html` · `tools/pr-calculator.html` · `tools/loss-calculator.html`

## 7. 검색 노출 (전국 대상이므로 중요)

### 등록

- **네이버 서치어드바이저** — <https://searchadvisor.naver.com> 에 사이트 등록 후
  `sitemap.xml` 주소를 직접 제출. 국내 B2B 문의는 네이버 유입이 큽니다.
- **구글 서치 콘솔** — <https://search.google.com/search-console> 동일하게 등록 후 사이트맵 제출.

> ⚠️ `robots.txt` 는 **도메인 루트에서만** 인식됩니다. 즉 크롤러는
> `two-hee.github.io/robots.txt` 를 읽고 `/solarcare/robots.txt` 는 무시합니다.
> 그래서 **사이트맵은 위 두 서비스에 직접 제출해야** 합니다.
> (자체 도메인으로 옮기면 `robots.txt` 가 정상 작동합니다.)

### 콘텐츠

검색 유입은 회사소개가 아니라 **진단 사례**에서 나옵니다. 홈의 "발전저하 요인" 8개 항목이
그 씨앗입니다. 각 항목마다 사례 페이지를 하나씩 만드세요.

권장 형식 — **증상 → 데이터상 특징 → 현장 확인 → 조치 → 회복된 발전량(kWh / 원)**

숫자로 끝나는 사례 5개가 회사소개 페이지 20장보다 강력합니다.

> 고객사명 · 발전소 정확한 주소 · 알아볼 수 있는 사진은 **사전 서면 동의 없이 올리지 마세요.**
> `○○시 480kW 지붕형` 처럼 익명 처리하는 것을 기본으로 하세요.

### 새 진단 사례 추가하는 순서

1. `cases/sample-shading-loss.html` 를 복사해 새 이름으로 저장 (예: `cases/pid-module-loss.html`)
2. 내용을 실제 사례로 교체합니다. 5단 구조(증상 → 데이터 → 현장 → 조치 → 회복)를 유지하세요.
3. **`<meta name="robots" content="noindex, nofollow">` 줄을 삭제** — 이게 남아 있으면 검색에 안 걸립니다.
4. 파일 상단의 `<div class="samplebar">…</div>` **예시 안내 배너를 삭제**합니다.
5. `<title>`, `description`, `canonical`, `og:*` 를 새 내용으로 교체합니다.
6. `cases/index.html` 의 `<article class="case-card">` 하나를 복사해 목록에 추가합니다.
   `data-cause="음영"` 에 원인 태그를 넣으면 상단 필터에 자동으로 걸립니다
   (여러 개면 공백 구분: `data-cause="음영 모듈"`).
7. `sitemap.xml` 에 새 주소를 추가합니다.

> `cases/index.html` 에 지금 들어 있는 3건은 **형식을 보여주기 위한 예시**입니다.
> 실제 실적이 아니므로 반드시 실제 사례로 교체하거나 삭제하세요.

### 계산기 기본값 점검

`tools/pr-calculator.html` 과 `tools/loss-calculator.html` 의 입력 기본값(SMP 130원,
REC 70,000원, 가중치 1.0 등)은 **예시**입니다. 시세가 바뀌면 갱신하세요.
방문자가 그대로 쓰고 오해하지 않도록, 두 페이지 모두 “간이 추정” 안내를 넣어두었습니다.

## 9. 법적 주의사항

- **표시광고법** — 1인 기업이 "다수의 전문 인력" 같은 표현을 쓰면 허위·과장광고가 될 수 있습니다.
  규모를 부풀리는 대신 대표자 실명 + 자격증 + 실제 사례로 신뢰를 만드세요.
- **디자인 참고** — 레이아웃·여백·정보구조 같은 일반적 디자인 관용구는 참고해도 되지만,
  특정 기업의 로고·시그니처 색·전용서체·카피는 쓸 수 없습니다.
  이 사이트의 네이비+오렌지골드 팔레트와 Pretendard 조합은 그런 충돌이 없는 구성입니다.
- **개인정보** — 문의 폼에 수집·이용 동의 체크박스를 넣어두었습니다. 수집 항목이나
  보유 기간을 바꾸면 `contact.html` 의 안내 문구도 함께 수정하세요.
